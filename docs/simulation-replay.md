# Input replay и snapshot digest

`SimulationReplay` воспроизводит расписание игровых команд в чистом Core без Godot и render FPS.
Это инструмент для регрессий управления/физики, а не запись/просмотр полёта из игрового UI.

## Контракт

- Новый мир: `worldSeed`, стандартный spawn в галактике 0 / системе 0, профиль и `FlightMode`.
- `tickSeconds` — конечный положительный фиксированный шаг; `tickCount` — число шагов.
- Индекс `ReplayCommand.Tick` начинается с 0: команда применяется **до** соответствующего `Advance`.
- Команды упорядочены по неубыванию тика. На одном тике сохраняется порядок входного списка;
  поле `Sequence` не используется для пересортировки.
- Сохраняется обычная семантика симуляции: тяга/поворот удерживаются до следующей команды.
- `Run` возвращает итоговый `SimulationSnapshot` и `SnapshotHash`.

```csharp
var commands = new[]
{
    new ReplayCommand(0, new MoveCommand(1, 0, 1.0, 0.0)),
    new ReplayCommand(60, new RotateCommand(1, 1, 0.4, 0.0, 0.25)),
    new ReplayCommand(120, new MoveCommand(1, 2, 0.0, 0.0)),
};
ReplayResult result = SimulationReplay.Run(0x51A7UL, 1.0 / 60.0, 180, commands);
```

Типы находятся в namespace `DarkSpace.Core.Simulation`.

## Канонизация v1

`SnapshotDigest.Compute` сериализует наблюдаемый снимок с invariant culture, рекурсивно сортирует
ключи объектов JSON через ordinal comparison, сохраняет порядок массивов и считает SHA-256 UTF-8.
Перед JSON записывается `darkspace-snapshot-v1` и LF. Результат — 64 hex-символа в нижнем регистре.
Порядок вставки ключей Cargo/TradeCargo и текущая культура ОС не влияют на результат.

Числа **не округляются**: даже изменение double на 1 ULP должно менять hash. NaN/Infinity отклоняются.
Снимок включает вычисляемые свойства сериализуемых типов, поэтому изменение его схемы или
сериализации требует проверки golden. Digest не включает скрытое состояние симуляции,
репутацию, отложенные команды или конфигурацию: это не save/checkpoint и не полный state hash.

## Golden flight v1

Тест `SimulationReplayTests.EliteFlight_MatchesReviewedGolden` фиксирует:

- сид `0x51A7`, `EliteAligned`, стандартный профиль;
- 480 тиков по 1/60 с (8 модельных секунд);
- тик 0: тяга 0.8;
- тик 60: pitch 0.4 / roll 0.25;
- тик 180: отпустить вращение;
- тик 300: торможение -1;
- тик 420: отпустить тягу, далее coast;
- итог: скорость 0, топливо 34 с допуском 1e-9, ненулевая пройденная дистанция,
  единичная норма ориентации.

Hash:

```text
2c912cecd702fb00e52844ea37a8428f66c66b5f3759b805c5a87ee5ad7bd798
```

Это явный baseline текущей модели, не эталон «идеального ощущения» полёта.
Не обновлять hash автоматически при падении теста: сначала проверить изменения состояния и формул.

## Проверки и ограничения

- Повторные прогоны и прогон после CommandCodec round-trip совпадают для EliteAligned/Newtonian.
- Проверяются изменение input/seed/profile/mode, порядок команд, границы тиков и ошибочные аргументы.
- GitHub Actions запускает общий unit suite на Linux и replay suite отдельно на Windows.
- Локальный результат Windows не доказывает кроссплатформенный детерминизм. Отличия libm/CPU/runtime
  могут менять младшие биты double; CI выявляет такие расхождения на проверяемых runners, но не на всех платформах.
- Нет runtime-рекордера, replay-плеера в UI и восстановления из произвольного snapshot.
