## 3. Принятые архитектурные решения (ADR-lite)

> Каждая запись: **Решение**, **Почему**, **Альтернативы**, **Последствия**.

### ADR-001: Godot 4.4+ (.NET) + C# 12 / .NET 8
- **Решение:** движок Godot 4.4+ с поддержкой .NET, основной язык C# (GDScript — только по необходимости).
- **Почему:** бесплатный движок с открытым кодом, первоклассная поддержка C#, быстрый прототипинг 3D и UI.
- **Альтернативы:** Unity (тяжелее, лицензирование), Unreal (оверкилл для скоуп-проекта), собственный движок (слишком долго).
- **Последствия:** зависим от версии .NET, поддерживаемой текущей сборкой Godot .NET.

### ADR-002: Разделение «чистое ядро» и «слой движка»
- **Решение:** вся игровая логика (генерация, экономика, алхимия, сохранения) живёт в чистом C# без зависимости от `Node`/`Vector3`.
- **Почему:** тестируемость без движка, детерминизм, переносимость, возможность headless-сервера.
- **Альтернативы:** писать всё сразу на `Node` (быстрее старт, но неподъёмное тестирование).
- **Последствия:** нужны DTO/мапперы на границе ядро↔движок; дисциплина обязательна.

### ADR-003: Детерминированный PRNG вместо `System.Random`
- **Решение:** собственный детерминированный генератор (`SplitMix64`/`Xoshiro`) для всех процедурных систем.
- **Почему:** воспроизводимость по сиду независимо от рантайма, .NET-версии и порядка вызовов; основа для мультиплеера и тестов.
- **Альтернативы:** `System.Random` (не гарантирует стабильность между версиями), `RandomNumberGenerator` (крипто, не нужен).
- **Последствия:** нужно самим реализовать и покрыть тестами; нельзя «дёшево» использовать `System.Random` в ленивых местах.

### ADR-004: 256 галактик с 8-битным индексом
- **Решение:** каждая галактика имеет уникальный 8-битный индекс (0–255), генерация — от (worldSeed, galaxyIndex).
- **Почему:** фиксированный масштаб вселенной, простые адреса/сохранения/синхронизация, галактика #256 (Odyalutai) как «пасхалка».
- **Последствия:** номер галактики — часть ключа генерации; миграция сидов должна это учитывать.

### ADR-005: Формат сохранений с обязательным `version`
- **Решение:** сохранения содержат поле `version`; сериализация — JSON (человекочитаемый) с возможностью бинарного режима.
- **Почему:** миграция старых сохранений, отладка, отказоустойчивость.
- **Последствия:** при каждом изменении схемы — миграция вверх + тест на совместимость.

## 4. Заметки о дизайне (не реализовано, но важно)

- **Процедурный звук:** генерация музыки/эффектов из паттернов по сиду (WebAudio-подобный синтез на стороне Godot `AudioStreamGenerator`).
- **Процедурные шейдеры:** планеты, звёзды, туманности, чёрные дыры — на `ShaderMaterial` + шум `FastNoiseLite`.
- **Чёрный юмор как система:** генератор описаний/реплик с шаблонами и «тоном» (сарказм, цинизм, бюрократия, религия, жадность), зависящим от фракции/контекста.
- **Алхимия:** 12–16 базовых элементов → комбинаторика; имена вида «Гидро-Железо», «Экто-Плазма»; опасные/абсурдные рецепты.
- **Экзотика:** нейтронные звёзды, чёрные дыры с «прыжком» в другую галактику, двойные системы.
- **Кооп («френдслоп»):** общий/личный прогресс (деньги, репутация, ресурсы) — настраиваемо на старте сессии.
- **Закрытая галактика #256 (Odyalutai)** — доступ через порталы/чит-коды; не входит в обычный поток навигации.
